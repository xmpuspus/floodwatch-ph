## 3. Architecture — what actually gets built

The corridor surface is a **restructure of `NowView.astro`** into the D2-B
tiered layout under the "Corridor watch" headline, plus a new client-fetch
layer and a freshness-clock module. No pipeline/EE changes for data emission.

New/changed runtime data flow:

```
EXISTING (daily cron, unchanged):
  event/flood_latest.py        -> /data/flood_latest.geojson (+_meta.as_of, scan_status)
  realtime/current_risk.py     -> /data/current_risk.geojson  (+_meta.as_of)
  pipeline/road_exposure.py    -> /data/road_flood_exposure.geojson (+_meta.expressway_summary, as_of)

NEW (client-side, fetched in-browser at view time, zero cron):
  site/src/lib/realtimeClient.ts
    - RainViewer:  GET api.rainviewer.com/public/weather-maps.json
                   -> newest radar.past frame -> XYZ tile layer (PAGASA/PANAHON)
    - GFM (SAR):   GET stac.eodc.eu/api/v1/search?collections=GFM&bbox=<Luzon>
                   &sortby=-properties.datetime&limit=1 -> titiler XYZ tilejson
    - VIIRS (NRT): GET gibs.earthdata.nasa.gov .../WMTSCapabilities.xml
                   -> resolve latest date -> WMTS XYZ (default OFF, subordinate)
  site/src/lib/freshnessClock.ts  -> per-layer ticking age + global ticker
  site/src/components/CorridorWatch.astro (the 1 new component, D1-A headline,
    D2-B tiers, reuses v1.1.0 scannable progressive-disclosure pattern)
```

Tier mapping (D2-B, kind-not-priority labels):
- **Freshest observation:** RainViewer rain radar (client, ~5-10 min, `nowcast`).
- **Dated ground truth:** existing Track A S1 flood extent + GFM faster-observed SAR (client, ≤8 h per pass). Observed-flood keeps hero z-order.
- **Supplementary, cloud-limited:** NASA VIIRS NRT optical (client, default-off).
- Rainfall accumulation context (`current_risk`) stays as the existing labeled context flag, not promoted.

CSP delta (`site/vercel.json` `connect-src` AND `img-src`, additive):
`https://api.rainviewer.com https://*.rainviewer.com https://tilecache.rainviewer.com https://gibs.earthdata.nasa.gov https://stac.eodc.eu https://titiler.services.eodc.eu`
— six public government/meteorological origins. No new server, no function, no
paid dep. Each origin gets one privacy-page sentence (purpose + "contains no
user input, identical bytes for every visitor"). The lookup-never-leaves-the-
browser invariant stays mathematically intact (fixed-bbox tiles, no user query
in any request).

## 5. Per-layer honest labels (from research §2, Agent F-gated — P0 finalizes verbatim)

- RainViewer: `Rain radar: PAGASA national radar via RainViewer — last frame {frameUTC} ({age} ago). Ground-radar observation, not a forecast. Source: RainViewer / PAGASA.`
- GFM: `Faster observed SAR flood: Copernicus EMS GFM ensemble, Sentinel-1 pass {DATETIME} (delivered <=8 h after acquisition). 20 m, all-weather radar. Observed, not a forecast; gaps where no recent S1 pass.` + the CC BY 4.0 / STAC-default note.
- VIIRS: `Supplementary observed flat-water signal: NASA LANCE VIIRS NRT flood, {DATE} 1-day composite. Optical (~250 m), cloud-limited — typhoon cloud often blanks it. Not the primary layer, not live, not a forecast.`
- Existing S1: `Latest usable Sentinel-1 SAR pass: {DATE}. S1A+S1C, ~6-day revisit, ~24 h product latency. Dated ground truth — not live, not a forecast.`
- Freshness clock (research §5, "now-ish" dropped): per-layer caption `{LAYER} · {ticking age} · acquired {YYYY-MM-DD HH:MM} UTC · source {source} · {latency class}`; global ticker names the freshest layer + its absolute timestamp + a "site rebuilt {UTC}; layers refresh independently" line. Neutral grey default; amber dot only when a layer is staler than its own cadence; never red, never pulsing; honest-empty (disabled toggle + reason) on client-fetch failure.
